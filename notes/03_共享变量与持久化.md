## 一、共享变量

Spark 程序在集群上运行时，Driver 与各 Executor 是**不同的进程**。Driver 端定义的普通变量会被**序列化复制**到每个 Task，Task 对它的修改**不会**回传 Driver。

共享变量就是为了解决「跨节点共享读写」而设计的两种特殊变量：

| 类型 | 方向 | 权限 |
| --- | --- | --- |
| 累加器 Accumulator | Executor → Driver 汇总 | Executor 可 add，Driver 读 |
| 广播变量 Broadcast | Driver → Executor 分发 | Driver 写，Executor 只读 |

---

## 二、累加器

```python
counter = sc.accumulator(0)
rdd = sc.parallelize(range(10))

def increment(x):
    # global counter      # 错误写法：靠 global 在集群上不生效
    # counter += x        # 错误写法：累加器不支持 +=
    counter.add(x)        # 正确：调用 Accumulator 的 add 方法

rdd.foreach(increment)
print("Counter value", counter.value)      # 45
```

**要点**

- 创建：Driver 端 `sc.accumulator(初值)`；
- 修改：Executor 端只能 `counter.add(x)`；
- 读取：只能在 Driver 端读 `counter.value`；
- `counter.add(x)` **只改累加器内部值，不会改变变量绑定**，因此不需要 `global`。

## 三、广播变量

定义在 Driver 端，分发到 Executor 端；**Executor 端的所有 Task 都可以读取（只读）这个变量**。

```python
b = sc.broadcast([1, 2, 3, 4, 5, 6])
print(b.value)                                                    # [1, 2, 3, 4, 5, 6]

b1 = sc.parallelize([0, 0]).flatMap(lambda x: b.value).collect()
print(b1)                                                         # [1..6, 1..6]

b.unpersist()                                                     # 释放
```

**优势**：不用广播时，每个 Task 各持一份副本；用广播后，**每个 Executor 只存一份**，该节点上所有 Task 共享。

## 四、RDD 的依赖关系

### 4.1 窄依赖（Narrow Dependency）

**一个父 RDD 的 Partition 只能被一个子 RDD 的 Partition 使用，一对一。**

- 例如：`map`、`filter`、`flatMap`、`union`；
- 特点：子分区只依赖确定的父分区，**不需要 shuffle**；
- 容错：某个分区丢失时，只需重算对应的那一个父分区。

### 4.2 宽依赖（Wide Dependency）

**一个父 RDD 的 Partition 会被多个子 RDD 的 Partition 使用，一对多。**

- 例如：`groupByKey`、`reduceByKey`、`sortBy`、`join`；
- 特点：需要跨节点**shuffle** 数据；
- 容错：某个分区丢失时，可能要重算**全部**父分区。

### 4.3 对比表

| 对比 | 窄依赖 | 宽依赖 |
| --- | --- | --- |
| 分区对应 | 一对一 | 一对多 |
| 是否 shuffle | 否 | 是 |
| 容错代价 | 低（只重算对应父分区） | 高（可能重算全部父分区） |
| 典型算子 | `map` / `filter` / `flatMap` / `union` | `groupByKey` / `reduceByKey` / `sortBy` / `join` |

## 五、DAG（有向无环图）

Spark 把 RDD 的转换序列组织成 **DAG（Directed Acyclic Graph，有向无环图）**。

**Stage 划分规则**：

> **通过宽依赖来划分 stage，窄依赖在一个 stage 内。**

```
Stage 1 (窄依赖链)  ──宽依赖(shuffle)──▶  Stage 2 (窄依赖链)
```

- 一个 stage 内部全是窄依赖，可以流水线（pipeline）执行，数据不必落盘；
- 遇到宽依赖就切断，形成新的 stage，shuffle 的数据要写磁盘/网络传输。

**为什么要这样划分**：stage 是任务调度和失败重算的基本单位；窄依赖链可以合并成一条流水线，减少中间数据的物化，提升效率。

## 六、RDD 的持久化

### 6.1 为什么需要持久化

**为避免多次重复计算同一个 RDD 的算子，将 RDD 缓存在磁盘或内存中，以达到持久化的目的。**

Spark 的 RDD 是惰性的，且默认**不保存计算结果**。如果一个 RDD 被多个 Action 或多个下游算子复用，不加缓存就会**从头重算整条血缘链**。

### 6.2 persist 与 cache

```python
rdd = sc.parallelize(['b', 'a', 'c'])
rdd.persist()
level = rdd.getStorageLevel()
print(level)        # Memory Serialized 1x Replicated
```

```python
rdd2 = sc.parallelize(['b', 'a', 'c'])
rdd2.persist(StorageLevel.DISK_ONLY_3)
print(rdd2.getStorageLevel())
```

| 方法 | 说明 |
| --- | --- |
| `cache()` | `persist()` 的简写，等价于 `persist(StorageLevel.MEMORY_ONLY)` |
| `persist(level)` | 指定存储级别 |
| `getStorageLevel()` | 查看当前存储级别 |
| `is_cached` | 是否已缓存 |
| `unpersist()` | 释放缓存 |

### 6.3 常见存储级别

| 级别 | 含义 |
| --- | --- |
| `MEMORY_ONLY` | 只存内存（默认，`cache()` 等价于此） |
| `MEMORY_AND_DISK` | 内存放不下就溢写到磁盘 |
| `DISK_ONLY` | 只存磁盘 |
| `MEMORY_ONLY_SER` | 序列化后存内存，省空间但读取要反序列化 |
| `DISK_ONLY_3` | 只存磁盘，副本数 3 |
| `OFF_HEAP` | 堆外内存 |

### 6.4 持久化的注意点

1. **惰性**：`persist()` 本身不触发计算，第一次 Action 时才真正缓存；
2. **用完要释放**：`unpersist()`，否则一直占用内存；
3. **不是越多越好**：缓存会占内存，只对**被复用**的 RDD 缓存才有收益。

## 七、本章小结与考点

1. 累加器：Driver 创建，Executor 用 `add()` 修改，Driver 读 `.value`；
2. 广播变量：Driver 创建分发，Executor 只读，每个 Executor 一份；
3. **窄依赖**一对一、无 shuffle；**宽依赖**一对多、需 shuffle；
4. **宽依赖划分 stage，窄依赖在同一 stage 内**；
5. DAG 是 RDD 转换形成的有向无环图，是调度与容错的基础；
6. `persist()` / `cache()` 用于避免重复计算，`cache()` = `MEMORY_ONLY`；
7. 持久化是**惰性**的，用完记得 `unpersist()`。
